## 0. 톤 위계 원칙

본 발표는 3개 톤(A/B/C)이 위계를 이루며, 발표 흐름에 시각적 리듬을 만든다.

- **Tone A · 임팩트형** — 표지·핵심 인사이트·결론
- **Tone B · 분석형** — 챕터 진입·본문 분석
- **Tone C · 데이터형** — 표·차트·비교 매트릭스

같은 톤이 연달아 등장하면 발표 리듬이 평탄해지므로, 슬라이드 배치 시 톤 교차를 의식한다.
다만 의도된 시퀀스(예: 같은 메시지의 2~3장 분할) 안에서는 같은 톤이 연속될 수 있다.

---

## 1. Tone A · 임팩트형

### 정의
청중의 시선을 한 점에 집중시키는 톤. 한 슬라이드 = 한 메시지 원칙이 가장 엄격하게 적용된다.
화면 안에 정보가 적고, 그 적은 정보가 큰 시각 비중을 차지한다.

### 사용 목적
- 표지 — 발표 첫 인상과 핵심 메시지 던지기
- 핵심 인사이트 — 한 슬라이드에 한 문장 또는 한 숫자만 큰 비중으로 강조
- KPI 임팩트 — 다운타임 114h → 52h 같은 단일 강조 수치
- 결론 회수 — 표지 메시지의 변주로 발표를 닫음

### 시각 규칙
- 배경: 기본은 `--color-paper`. `--color-bg-cream`은 메시지 박스나 일부 영역에 사용하며, 전체 배경으로 사용할 때는 사용자 확인
- 정보 밀도: **매우 낮음** (한 슬라이드 시각 요소 1~3개)
- 타이포그래피 위계: 매우 큼. 제목 또는 단일 KPI가 화면의 큰 비중을 차지
- 강조 색상: 브랜드 레드(`--color-red`) 또는 `--color-ink-strong` 중심
- 여백: 충분히 확보. 시선이 분산되지 않게 함

### 사용 대상 슬라이드 유형
- 표지
- 핵심 주장 카드
- 단일 KPI 임팩트 (다운타임 KPI 등)
- 호황기 재무 카드 — 단독 Tone A로 사용 시 반드시 "자금 여유"가 아닌 "성장 기반 정비" 메시지와 함께 사용
- 결론 카드

### 사용 컴포넌트
- `.cover-title` + `.t-em`
- `.cover-message` + `.msg-hl`
- `.count[data-target]` (카운트업 단일 강조)
- `.kpi-card`는 단일 KPI 임팩트 페이지에서 제한적으로 사용
- 화면 비중이 부족하면 사용자 승인 후 `.impact-kpi` 계열 컴포넌트를 정의한다 (정의 예정)

### 금지
- 한 슬라이드에 KPI 카드 4개 동시 노출 → Tone C로 분리
- 본문 분석성 텍스트 다수 → Tone B로 이동
- 표·차트 → Tone C로 이동

---

## 2. Tone B · 분석형

### 정의
한 메시지를 도식·다이어그램·흐름으로 설명하는 톤. 본문의 주력 톤.
정보 밀도는 중간이며, 시각 요소가 메시지를 직접 뒷받침한다.

### 사용 목적
- 챕터 진입 — 다음 챕터의 화두 던지기
- 본문 분석 — 도식·다이어그램·흐름으로 한 메시지 입증
- 시퀀스 시작·종료 — 시퀀스 안에서 분석 흐름 안내
- 메시지 카드 — 한 문장의 분석 명제를 시각적으로 받쳐줌

### 시각 규칙
- 배경: `--color-paper` 또는 `--color-bg`
- 정보 밀도: **중간** (시각 요소 3~6개)
- 타이포그래피: 제목 명확 + 분석성 본문 1~2단락 또는 도식 라벨
- 강조 색상: 브랜드 레드는 핵심 노드 1개 또는 핵심 키워드 1개에만 제한
- 도식 우선: 텍스트보다 도식이 메시지를 전달

### 사용 대상 슬라이드 유형
- 챕터 진입 풀배경 (선택적 — slides.yml에서 결정)
- 거버넌스 3축 도식
- 4대 제약 조건 카드
- 방법론 진화 흐름
- 누적 SAP 자산 타임라인
- 타사 벤치마크 시간 축
- 보강 A "왜 계열사 시스템이 다른가" 분석 카드
- SAP 중심 + 주변 시스템 도식 (주변 시스템 3~4개를 개념적으로 설명하는 경우)

### 사용 컴포넌트
- `.eyebrow` + 챕터 제목
- `.process-pipe`
- `.integration-svg` (3사 통합 구조도 — 단, 거버넌스 3축과 시각 구분)
- 정의 예정 컴포넌트는 §3-1 참조

### 금지
- 표 형식의 데이터 비교 → Tone C로 이동
- 단일 큰 숫자 임팩트 → Tone A로 이동
- 5개 이상 정보 밀집 → Tone C로 이동 또는 시퀀스 분할

## 3. Tone C · 데이터형

### 정의
표·차트·매트릭스·비교 카드 등 정량 데이터와 구조화된 정보를 다루는 톤.
정보 밀도가 가장 높으며, 청중이 데이터를 읽고 비교하는 시간이 필요하다.

### 사용 목적
- 표·매트릭스 — 4대 대안 비교, 산업 특성 6개, IT 5대 제약 등
- 데이터 비교 — 좌우 분할 비교 (롯데 vs 현대차, 초기 목표 vs PIR 성과)
- 다중 KPI — 정량 4지표 4분할 카드
- 시스템·플랫폼 도식 — SAP 중심 + 주변 시스템 EAI (정보량 많은 경우)

### 시각 규칙
- 배경: 기본은 `--color-paper`. 카드·표 내부 구분에만 `--color-bg-cream` 또는 `--color-bg-warm`을 제한적으로 사용
- 정보 밀도: **높음** (시각 요소 4~8개 또는 표 셀 다수)
- 타이포그래피: 정량 수치·라벨 가독성 우선
- 강조 색상: 표 안의 한 행/한 셀 또는 선택된 대안 1개에만 브랜드 레드
- 비교 균형: 좌우 비교 시 양측 톤이 동등해야 함 (특히 보강 F)

### 사용 대상 슬라이드 유형
- 4대 대안 비교 매트릭스
- 산업 특성 6개 카드
- IT 5대 제약 카드
- GAP 3트랙 (BPR/Customizing/Add-on)
- SAP 중심 + 주변 시스템 도식 — 주변 시스템 6개를 모두 배치하고 경계·연계를 설명하는 경우 (보강 D, EHS 경계 위 표현)
- 롯데 온프레 vs 현대차 클라우드 비교 카드 (보강 F)
- PIR 정량 4지표 4분할
- 초기 목표 ↔ PIR 성과 매칭

### 사용 컴포넌트
- 기존: `.kpi-card`(다중 KPI 그리드), `.count[data-target]`(다중 카운트업)
- 정의 예정: §3-1 참조

### 금지
- 표 안의 모든 셀에 강조 색상 사용
- 좌우 비교에서 한쪽이 시각적으로 우위로 보이게 표현
- 시각 요소 9개 이상 (시퀀스 분할 필요)

## 3-1. 신규 컴포넌트 사용 주의

이 문서에 언급된 신규 컴포넌트는 실제 HTML에 바로 사용할 수 없다.
상태가 정의 예정인 컴포넌트는 `spec/component-catalog.md`에 등록하고
사용자 승인을 받은 뒤 `shared/style.css`에 정의해야 한다.

### 정의 예정 후보
- `.governance-triad` — Tone B, 거버넌스 3축
- `.timeline` — Tone B, 시간 축 (Step1 누적 자산 / 타사 벤치마크)
- `.decision-matrix` — Tone C, 4대 대안 비교
- `.strategy-track` — Tone C, GAP 3트랙 (BPR/Customizing/Add-on)
- `.platform-hub` — Tone B 또는 Tone C, SAP 중심 + 주변 시스템 EAI
- `.compare-card` — Tone C, 좌우 2분할 비교 (롯데 vs 현대차)
- `.impact-kpi` — Tone A, 단일 KPI 대형 임팩트

각 컴포넌트의 활성화는 해당 슬라이드 빌드 직전 사용자 승인을 거친다.

## 4. 톤 경계 판단 — 도식 슬라이드의 특수 사례

도식 슬라이드는 정보량에 따라 Tone B 또는 Tone C로 갈린다.

### SAP 중심 + 주변 시스템 도식 (보강 D)
- 주변 시스템 3~4개를 개념적으로 설명 → **Tone B**
- SCM·MES·PLM·LIMS·EHS·GEMS 6개 모두 배치 + 경계·연계 설명 → **Tone C**

본 발표에서는 6개 모두 배치하므로 Tone C로 분류한다. 다만 시퀀스로 분할할 경우 첫 장(질문 던지기)은 Tone B 가능.

### 시간 축·타임라인
- 흐름 강조 중심이면 Tone B (Step1 누적 자산 타임라인)
- 다수 항목 비교가 핵심이면 Tone C (타사 벤치마크 5사 비교)

## 5. 톤 교차 원칙

### 챕터 안의 톤 흐름

한 챕터 안에서 다음 흐름이 자연스럽다:

**B (챕터 진입) → C (데이터·분석) → A (핵심 인사이트) → B (연결)**

또는 (시퀀스 분할 시):

**B (질문) → C (분석) → C (분석) → B (결론)**

### 톤 연속 허용 조건

같은 톤이 연속되는 것은 다음 조건에서만 허용된다:

- **시퀀스 분할 안에서** — 한 메시지를 2~4장으로 쪼개는 경우 같은 톤 연속 가능
  - 예: GAP 3트랙, 보강 F 비교 등은 필요 시 2~3장 시퀀스로 분할 가능
- **결론 챕터에서** — 결론은 Tone A가 중심이므로 연속 가능

### Tone C 연속 시 주의

Tone C는 정보 밀도가 높기 때문에 3장 이상 연속될 경우 발표자가 반드시 중간 요약 문장을 넣는다.
가능하면 Tone C 2~3장 뒤에는 Tone B 또는 Tone A로 핵심을 회수한다.

### 톤 비율 가이드

본 발표 전체의 권장 분포:
- Tone A: 약 20% 내외
- Tone B: 약 30% 내외
- Tone C: 약 50% 내외

후보안 C'' 기준으로는 Tone A 6장, Tone B 8~10장, Tone C 13~15장을 참고한다.
이는 권장 비율이며, 실제 배치는 `outline/slides.yml`에서 확정한다.

## 6. 톤 결정 기준 (의사결정 트리)

새로운 슬라이드의 톤을 결정할 때 다음 순서로 판단한다.

1. **이 슬라이드의 핵심이 표·매트릭스·다중 데이터인가?**
   → **Tone C**

2. **이 슬라이드의 핵심이 단일 인상·단일 메시지·단일 숫자인가?**
   → **Tone A**

3. **이 슬라이드의 핵심이 도식·흐름·분석 명제인가?**
   → **Tone B**

### 보조 기준 (시각 요소 개수)

시각 요소 개수는 보조 기준이다.

- 1~3개 → Tone A
- 4~6개 → Tone B
- 7개 이상 → Tone C 우선 검토

시각 요소가 7개 이상이어도 흐름을 설명하는 목적이면 Tone B를 유지할 수 있다.
다만 비교·선택·평가가 필요한 구조라면 Tone C로 분류한다.
