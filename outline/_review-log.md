## Step1 · 기업 선정 및 산업 특성 분석 (확정 2026.05.22)

### 발표 반영 결정

**타임라인**
- 풀버전 9개 시점은 로그에 보관
- 실제 발표에서는 **2003 SMART → 2010 GEMS → 2017 S/4HANA** 3대 핵심 축을 강조
- 나머지 2012·2015·2016·2018·2020은 보조 타임라인으로 처리

**호황기 강조**: 채택
- 2017 매출 15.8조 / 영업이익 2.93조(사상 최대)를 카드로 활용
- **해석 방향 고정**: "위기 대응형이 아닌, 성장 이후 통합 운영 기반을 선제적으로 정비한 결정"
- 금지 해석: "호황이라 돈이 많아서 ERP를 했다"

**학술 인용**
- 이상신(2020)의 석유화학 IT 시스템 5대 제약만 본문 시각화
- 본문에서는 "이상신 5대 특성"이 아닌 발표용 제목 사용 (예: "석유화학 산업은 왜 ERP 전환이 어려운가?")
- 김근옥(2019), 박주황(2014)은 출처 페이지 또는 발표자 노트에만 보관

**산업 특성**
- 6개 모두 outline에 포함
- 발표 슬라이드에서는 핵심 3개 중심으로 설명 (예: 연속공정·글로벌 다거점·규제 대응)
- 산업 특성 6개 + IT 제약 5개를 한 슬라이드에 11개 요소로 모두 나열하지 않는다

**M&A 트리거**: 약 2.8조 원 인수 (정밀화학 4,650억 + 첨단소재 2조 3,265억)
- Step1에서 한 번 쓰고 끝내지 않음
- 3사 기준정보·업무 프로세스 통합 압력의 직접 근거로 Step2~Step4까지 반복 등장

**10개 핵심 업무**: 위치 조정
- Step1에서는 통합 규모의 보조 지표로만 사용
- 세부 모듈 목록은 Step3/Step4에서 본격 활용

**박제성 정보전략담당 상무 인터뷰**
- 공개자료 중 프로젝트 목적·성과 수치를 직접 확인할 수 있는 핵심 1차 발언 자료 (테크수다)
- 단, Step4에서 내부자 자기평가의 한계도 함께 언급 필요

### 슬라이드 후보 컴포넌트 (번호 미부여)

- **산업 배경 카드**: 산업 특성 6개 + IT 시스템 5대 제약을 좌우 나란히 배치, 핵심 메시지 1개
- **도입 계기 카드**: 2017 호황기 (15.8조 / 2.93조) + 2016 M&A 2.8조 결합
- **누적 자산 타임라인**: 2003 SMART → 2010 GEMS → 2017 S/4HANA 3대 축 + 보조 시점

### 핵심 출처
[1] 테크수다 박제성 인터뷰 / [8] 2017 사업보고서(DART) / [11] 이상신 박사논문

### 주의 사항
- 2017 호황기 재무는 "자금 여유"가 아니라 "성장 기반 정비"의 근거로 표현한다.
- 타임라인 9개 시점은 발표 슬라이드에 모두 같은 비중으로 넣지 않는다.
- 이상신(2020)은 학술 근거로 좋지만, 발표 본문에서는 "IT 시스템 제약"이라는 쉬운 표현으로 바꾼다.
- 김근옥(2019), 박주황(2014)은 본문 노출보다 출처 페이지 처리.

## Step2 · 솔루션 선정 및 타당성 분석 (확정 2026.05.22)

### 핵심 주장
본 사례의 솔루션 선정은 "새 ERP를 살 것인가"가 아니라,
**13년간 축적한 SAP 운영 자산 위에서 3사 통합과 글로벌 운영을 어떻게 고도화할 것인가**의 문제였다.
의사결정의 중심은 단순 Make/Buy가 아니라, 기존 SAP 자산을 활용한 **통합형 컨버전**으로 이동했다.

### 발표 반영 결정

**1. 거버넌스 3축 채택**
- 롯데케미칼 / 롯데정보통신 / SAP 본사 — Step2의 시그니처 도식
- 명확한 구분: "업무 통합 대상 3사"가 아닌 "프로젝트 추진 주체"
- 핵심 메시지: 외부 SI 일임이 아닌, 그룹 IT 자산 통제권 유지를 위한 전략적 추진 구조

**2. 4대 대안 비교 매트릭스 채택**
- A. 기존 SAP 기반 S/4HANA 전환 (선택)
- B. SAP Greenfield 신규 구축
- C. Oracle·MS Dynamics 등 타 ERP 전면 교체
- D. 현행 SAP 유지 + 별도 통합 시스템
- **5대 타당성은 별도 슬라이드화하지 않고 매트릭스의 평가 기준으로 흡수**
- 핵심 메시지: 13년 누적 SAP 자산 + 3사 통합 + 차세대 고도화 동시 달성 → A안 현실적

**3. Brownfield 표현은 본문 한 줄로 신중하게 처리**
- 단정 금지: SAP 공식 Brownfield 분류였다고 단정하지 않음
- 표현: "Brownfield 성격의 통합형 컨버전" 또는 "기존 SAP 자산을 활용한 통합형 컨버전"
- 매트릭스 슬라이드 하단 작은 주의 문장으로

**4. 경제적 타당성은 투자비 비공개 한계를 솔직히 표시**
- 구체 투자비는 공개자료에서 확인되지 않음 → 직접 ROI 계산 안 함
- 대신 **비용 회피 구조**로 분석: 기준정보 재활용 / 교육비 부담 축소 / 인터페이스 재설계 부담 감소 / 중복 운영비 감소
- 별도 슬라이드화 안 함 — 매트릭스 슬라이드 하단 또는 발표자 노트

**5. 강의 6단계 매핑은 별도 슬라이드화하지 않음**
- 본문 슬라이드에서 제외
- 결론 또는 발표자 노트에서 "ERP 도입 라이프사이클을 확인할 수 있는 사례"라는 한 줄로만 연결

### 슬라이드 후보 컴포넌트 (번호 미부여)

**솔루션 선정 추진 구조**
- 거버넌스 3축 도식 (롯데케미칼 / 롯데정보통신 / SAP 본사)
- 하단: 2018 그룹공통시스템·디지털혁신협의체 의결로 후속 효과 확인
- 메시지: ERP 전환은 그룹 IT 자산 통제권을 유지하는 전략적 추진 구조 위에서 진행되었다

**대안 비교와 선택 논리**
- 4대 대안 비교 매트릭스 (decision-matrix 컴포넌트)
- 하단 주의 문장: 공식 Brownfield 분류 단정 금지, 통합형 컨버전으로 표현
- 메시지: 기존 SAP 자산을 활용한 S/4HANA 전환이 가장 현실적인 선택이었다

### 컴포넌트 활성화 필요 (Phase 3 빌드 직전 사용자 승인)

- `.decision-matrix` — CLAUDE.md §3-4 정의 예정 컴포넌트. 본 슬라이드에서 처음 활성화. 카탈로그 등재 필요.
- `.governance-triad` (가칭) — **신규 컴포넌트**. 카탈로그에 미등록.
  - 디자인 가이드라인: 기존 `.integration-svg`(3사 통합 다이어그램)와 **시각적으로 명확히 구분**되어야 함.
  - "업무 통합 대상" vs "프로젝트 추진 주체"의 혼동을 도식 단위에서 차단.
  - 노드 라벨 컨벤션(§3-5)은 3사용이므로 이 도식에는 적용 안 됨 — 별도 컨벤션 필요.

### 발표에서 반드시 사용할 자료

- 4대 도입 목적 (3사 통합 / 글로벌 거점 지원 / 중복 투자 리스크 축소 / 디지털 코어 확보)
- 거버넌스 3축
- 4대 대안 비교 매트릭스
- 13년 누적 SAP 자산
- M&A 인수 자산 약 2.8조원
- 투자비 비공개에 따른 정성적 경제성 분석
- 2018 이사회 후속 의결 2건 (2018.02.08 + 2018.12.19)

### 발표에서 제외 또는 축소할 자료

- 강의 6단계 매핑표 단독 슬라이드
- Escrow 협약 보충 설명
- 이상신 PPM 모델 상세
- ERP/CRM 클라우드 적용률 (21.5%, 10.5%)
- Make vs Buy 1차 의사결정표 단독 슬라이드
- 5대 타당성 평가표 단독 슬라이드

### 주의 사항

- "Brownfield"라고 단정하지 않는다.
- "투자 효과가 입증됐다"라고 단정하지 않는다. 투자비 비공개 한계를 명시한다.
- 5대 타당성을 슬라이드 본문에 모두 펼치지 않는다.
- Make/Buy 1차 의사결정은 도입부 한 줄로만 처리하고, 4대 대안 비교에 집중한다.
- 거버넌스 3축 도식과 3사 통합 구조도를 디자인적으로 혼동하지 않는다.

## Step3 · 구축 단계의 의사결정과 리스크 관리 (확정 2026.05.22)

### 핵심 주장
본 단계의 본질은 7개월 압축 일정 안에서, 24시간 연속 가동되는 석유화학 3사 시스템을 통합하기 위해
방법론·범위·GAP·리스크를 동시에 통제한 의사결정 연쇄다.
Step3는 "무엇을 선택했는가"가 아니라 **선택한 SAP S/4HANA 전환을 어떻게 안전하게 실행했는가**를 설명하는 단계.

### 발표 반영 결정

**1. 4대 제약 조건 채택 — Step3 진입 카드**
- Time: 7개월 압축 일정
- Business Continuity: 24시간 연속 가동
- Multi-Entity: 3사 병존 운영
- Global Multi-Site: 해외 6개국 + 110개국 수출
- 메시지: 네 가지 제약이 동시에 충돌한 고난도 통합 프로젝트

**2. 다운타임 KPI 단독 강조 채택**
- 진단 114시간 → 실제 52시간 (-54%, 약 62시간 단축)
- 메인 표현: "114h → 52h" 흐름 + 보조 "62시간 단축" + "-54%"
- "62시간 단축"이 발표자 설명에 더 직관적이므로 함께 강조
- 위치: Step3 후반 또는 Step4 진입 직전 — 발표 흐름 후보안 단계에서 최종 확정
- 메시지: 다운타임 통제는 구축 단계의 리스크 관리가 실제로 작동했는지 보여주는 핵심 지표

**3. GAP 해결 3트랙 채택 — Step3의 핵심 의사결정 도식**
- BPR: 기준정보·재무회계·구매물류 등 표준화 영역
- Customizing: 각 사 본연 경쟁력·특화 프로세스 유지 영역
- Add-on: SCM·MES·PLM·LIMS·EHS·GEMS 등 비SAP 연계 영역
- 메시지: 모든 것을 강제 표준화하지 않고, 표준화할 것과 차별화로 남길 것을 구분했다

**4. 4대 방법론 비교표 폐기 — 진화 흐름으로 변형**
- Step2 4대 대안 매트릭스와 시각 중복 회피
- 변형: 2003 SMART(Big Bang) → 2010 GEMS → 2017 S/4HANA(Roll-out + 통합형 컨버전)
- Step1 타임라인과 시각적 연결 확보
- 메시지: 시스템 환경의 복잡도에 따라 구축 방식이 진화했다

**5. 6대 리스크 매트릭스 → 핵심 3개로 압축**
- 본문 노출: 다운타임 / 비즈니스 영속성 / 변경관리
- 다운타임은 별도 KPI 슬라이드로 분리되므로, 매트릭스에서는 "사전 진단·반복 검증" 통제 메커니즘만 표시
- 발표자 노트로 이동: 납기·재고, 중복투자, 벤더 종속 (Lock-in)
- 벤더 종속은 Step2 거버넌스에서 일부 다뤄졌으므로 본문 반복 금지

**6. AS-IS / TO-BE 6대 비교는 Step4로 이전**
- Step3 = 어떻게 구축했는가 / Step4 = 그래서 무엇이 달라졌는가
- 역할 분리 명확화

### 슬라이드 후보 컴포넌트 (번호 미부여)

**구축 난이도와 4대 제약**
- 시각화: 4대 제약 조건 카드 4분할
- 메시지: 이 프로젝트는 네 가지 제약이 동시에 충돌한 고난도 통합 프로젝트였다

**실행 전략: Roll-out과 GAP 3트랙**
- 시각화 상단: 방법론 진화 흐름 (2003 Big Bang → 2017 Roll-out)
- 시각화 하단: BPR / Customizing / Add-on 3트랙 (.strategy-track 컴포넌트)
- 메시지: 기존 자산을 활용하면서 표준화와 차별화를 균형 있게 조정했다

**리스크 통제 KPI**
- 시각화: 114h → 52h 대형 숫자 + -54% + 약 62시간 단축
- 메시지: SAP Value Assurance를 통한 사전 점검·반복 검증이 실제 다운타임 단축으로 검증되었다
- 위치 후보: Step3 후반 OR Step4 직전 (발표 흐름 단계에서 확정)

### 컴포넌트 활성화 필요 (Phase 3 빌드 직전 사용자 승인)

**신규 컴포넌트 후보**
- 이름 후보 (빌드 직전 확정):
  - `.three-track` — "3트랙" 구조 직설적, 좁음
  - `.strategy-track` ★ 추천 — 의미 보존 + 재사용 여지
  - `.track-grid` — 가장 범용, 의미 휘발 가능
- 용도: BPR / Customizing / Add-on 3트랙 구조 표현
- 사용 위치: Step3 실행 전략 슬라이드
- 조건: shared/style.css + spec/component-catalog.md 동시 등록 후 사용

**기존 컴포넌트 활용**
- `.kpi-card` + `.count[data-target]` → 다운타임 KPI 슬라이드 (기존 컴포넌트로 충분)
- `.process-pipe` → 방법론 진화 흐름 시각화 후보

### 발표에서 반드시 사용할 자료

- 7개월 구축 기간 (vs SAP 표준 18~24개월)

## Step4 · 도입 성과 및 구현 후 검토(PIR) (확정 2026.05.22)
